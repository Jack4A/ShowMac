Zero menu insets and warning curves — 2026-11-03

Request
Make component inner padding adjustable down to zero. All menu padding and
spacing defaults must be zero. Monitoring curves should use warning colors
when their readings exceed the applicable thresholds.

Implementation
Settings > 字体与外观 now has three independent native controls:
- 整体外边距: left/right padding of the whole menu group, 0–20 pt.
- 组件内边距: left/right padding within each component, 0–20 pt.
- 项目间距: spacing between components, 0–16 pt.
All missing/invalid preference defaults are zero. Existing valid preferences
remain user-controlled. Quick layouts now default to zero component spacing
and retain the independently chosen inner/outer padding.

The custom menu renderer measures the actual displayed value. It no longer
reserves the widest possible number and centers shorter numbers within that
reservation. Removed hidden prefix and graph/value gaps and forced extra
divider spacing. Status item length uses the full rendered image width.
Number widths intentionally change with the displayed digit count. Font,
units, icons, per-component black/white or custom colors and sensor identity
are preserved. macOS placement of other applications' status items is not
controlled by this setting.

MetricWarningBands shares display rules across menu curves, status popover,
dashboard sparklines, metric details, common sensor trends and the temperature
timeline. CPU usage retains its existing >=70% orange / sustained >=90% for
10 seconds red rule. CPU temperature uses >=80°C orange / >=90°C red; GPU
temperature uses >=75°C orange / >=85°C red, matching the existing diagnostic
bands. These are display thresholds, not changes to hardware control or safety
limits. Known raw CPU/GPU temperature probes use the same classification.
No invented threshold is applied to power, fan RPM, storage, battery, voltage,
current or memory readings. The fan curve editor is unchanged.

The existing 曲线告警色 preference remains enabled by default. Disabling it
restores ordinary curve colors. Alert runs preserve real sample dates/values,
missing-data gaps and segment boundaries; the temperature timeline retains
normal operating-mode colors. Six new localization keys are complete in all
six translated languages; all previous localization entries are unchanged.
